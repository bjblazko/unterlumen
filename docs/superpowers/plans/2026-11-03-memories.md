# Memories Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new place *Memories* (German *Erinnerungen*) that shows photos from today's date in earlier years, plus cards for a trip, a person, this month in earlier years and rediscovered photos, chosen without star ratings.

**Architecture:** One set-based read per library (`Store.MemoryPhotos`) gathers every dated, non-video photo inside the shared filter, together with what it shows (things, named people, main hue, tone, `dhash`, place). `Manager.MemoryPhotos` merges the libraries and caches the result under a change key. A new package `internal/memories` holds the pure selection and the kinds; `internal/api/memories` serves an overview and a detail page. The browser gets a place `memories` with an overview and detail pages at `#memories/<kind>/<key>`.

**Tech Stack:** Go (stdlib, SQLite through the existing `library.Store`), vanilla JS/CSS, Playwright e2e.

**Spec:** `/Users/blazko/.claude/plans/neues-feature-memories-schoene-encapsulated-octopus.md`. Task 1 copies it into the repo as `doc/features/open/2026-11-03-memories.md`; read both.

## Global Constraints

- Stars never count: the handler clears `Filter.Rating`, `Filter.From` and `Filter.Until`. No code in `internal/memories` reads `Rating`.
- No new stored state: no table, no sidecar write, no localStorage beyond what existing components use.
- No outbound network and no new dependency.
- SQL is set-based (`IN (SELECT …)`), never correlated. Each new query gets a plan test like `TestPersonFilterIsNotCorrelated` (`internal/library/store_query_test.go:117`). Reads go through `Manager.OpenFiltered` (a reader).
- A photo found in two libraries is shown once: keep the first library in `filterLibraries` order.
- UI copy is English keys translated in `src/web/i18n/de.js`. Copy is in sentence case with no exclamation marks. Dates go through `formatDay` and counts through `countHTML`/`countText`. No orange: there is no `btn-accent` here. Use the `huepattl-rams-design` skill for every UI step.
- Coding standards (CLAUDE.md, ADR-0015): functions of about 40 lines at most, one responsibility per file, and a `_test.go` for each new package.
- Fixed values: moment gap **30 min**; same look **`HashDistance <= 10`**; **5** picks per memory; trip **> 100 km** from home, at most **2** days between away days (the same rule as `findJourneys`); a trip or birthday counts when it falls within **±7 / +7 days** of today; a person rotates in when they have photos in **≥ 3** years; the rediscovered pool is the **top 5 %** by rarity.

## Review Focus

1. **A library with no GPS, no faces or no things (the appearance pass not run yet).** The page must still show "On this day" with picks; cards whose data is missing are simply absent. → Test `TestOverviewWithoutPlacesPeopleOrThings` (Task 4).
2. **29 February, and today being 28 February in a non-leap year.** → `TestOnThisDayLeapDay` (Task 4).
3. **Hundreds of burst shots in one minute.** Exactly one pick from that moment. → `TestPickOneMomentOneBurst` (Task 3).
4. **A malformed `day` parameter or an unknown kind/key in the detail request.** Answer with 400 and 404 sentences, never a panic. → `TestHandlerRejectsBadDay`, `TestDetailUnknownKey` (Task 5).
5. **A named person in the filter.** Every kind then contains only photos of that person, and the counts agree with the detail grid. → `TestOverviewCountsMatchDetail` (Task 4) and the e2e filter step (Task 7).

### Task 3: Selection: `internal/memories/pick.go`, `rarity.go`

**Files:**
- Create: `src/internal/memories/pick.go`, `src/internal/memories/rarity.go`, `src/internal/memories/home.go`
- Test: `src/internal/memories/pick_test.go`, `src/internal/memories/rarity_test.go`

**Interfaces:**
- Consumes: `library.MemoryPhoto`, `appearance.HashDistance`.
- Produces:
```go
func Eligible(p library.MemoryPhoto) bool // false for things screenshot, document, blurred, underexposed, overexposed
type Home struct{ Lat, Lon float64; Known bool }
func FindHome(all []library.MemoryPhoto) Home // 0.1° cell with most located photos, cell centre (as findJourneys: round(lat*10)/10)
func KmBetween(aLat, aLon, bLat, bLon float64) float64 // haversine, 12742 * asin(…), as stats-places-charts.js
type Rarity struct{ /* share per feature */ }
func NewRarity(all []library.MemoryPhoto, home Home) Rarity
func (r Rarity) Of(p library.MemoryPhoto) float64
func Pick(cands []library.MemoryPhoto, r Rarity, seed string, n int) []library.MemoryPhoto // best first
func Score(p library.MemoryPhoto, r Rarity, seed string) float64
```
- `Of`: the features are each thing, `"hue:<bin>"` when `HueBin >= 0`, `"tone:<key>"` when the key is `low` or `high`, and `"away"` when the photo is located, home is known and the photo is more than 100 km away. Each feature's share is its count among the eligible photos of `all`. Rarity = **max** over the features of `−ln(share)`, and 0 when there are none.
- `Score` = `100·len(People) + r.Of(p) + 0.05·jitter`. Jitter = `fnv64a(seed+"|"+p.ID)` mapped to [0,1).
- `Pick`:
  1. keep the eligible photos;
  2. sort them by `Taken`;
  3. split into moments where the gap is more than 30 min (`time.Parse("2006-01-02T15:04:05", Taken[:19])`; an unparsable date is a moment of its own);
  4. take each moment's highest `Score`;
  5. order these winners by score;
  6. take them in that order, skipping one whose dhash is ≤ 10 from an already-taken one (both `Hashed`), until there are `n`.

### Task 4: The kinds and the overview

**Files:**

**Interfaces:**
- Consumes: Task 3; `birthdays.Of`, `birthdays.AgeAt` (`internal/birthdays/birthdays.go`).
- Produces (the JSON tags are the API's, see Task 5):
```go
type Photo struct{ Lib, ID, Name, Taken string; Ratio float64 } // json lib,id,name,taken,ratio
type Year struct{ Year, Ago int; Date string; Total int; Picks []Photo }         // json year,ago,date,total,picks
type Card struct {
    Kind, Key string; Total int; Cover Photo                                        // kind: trip|person|month|rediscovered
    Start, End, Country string; Days int                                            // trip
    Name, Birthday string; Age *int                                                 // person; Birthday "" when it is not one
    Month int                                                                       // month
} // json kind,key,total,cover,start,end,country,days,name,birthday,age,month (omitempty)
type Overview struct{ Day string; Years []Year; Cards []Card }
type Detail struct{ Card; Picks, Photos []Photo }                                  // Photos: all eligible photos of the memory, time order
func Build(day time.Time, all []library.MemoryPhoto, births map[string]string) Overview
func BuildDetail(day time.Time, kind, key string, all []library.MemoryPhoto, births map[string]string) (Detail, bool)
type Trip struct{ Start, End, Country string; Photos int }
func FindTrips(all []library.MemoryPhoto, home Home) []Trip // port of findJourneys: day centre weighted by photo count, >100 km, end→day ≤ 3 calendar days apart joins; country = most photos
```
- **Seed** = `day.Format("2006-01-02") + "|" + kind + "|" + key`.
- **Picks** are 5 per memory, best first from `Pick`, then sorted by `Taken` for display. `Cover` is the best one.
- **On this day** (`key` = the date): a photo counts when its month-day equals today's, its year is earlier than today's, and the date is valid. When today is 28 Feb in a non-leap year, 29 Feb photos count too. Years run newest first. `Ago` = today's year − the photo's year.
- **Month** (`key` = `"MM"`): today's month in earlier years. One pick per year (`Pick(n=1)` per year), shown in time order. There is no card when fewer than 2 years have photos.
- **Trip** (`key` = start date): among the trips of earlier years whose start month-day lies within ±7 days of today's, take the most recent. Otherwise take `trips[fnv(seed) % len]` among the trips that ended before today. The trip's photos are all photos whose day lies in [Start, End]. There is no card without trips.
- **Person** (`key` = the name):
  - Look for a birthday in 0…7 days: the soonest one, among people with at least one photo. `Birthday` = this year's date and `Age` = `AgeAt(birth, birthdayThisYear)`. Picks are one per year since the birth year.
  - Otherwise take a person with photos in ≥ 3 distinct years, by `fnv(seed)` over the names sorted. Picks are one per year, the newest 5 years.
  - The person's photos are all of their photos in the years shown.
- **Rediscovered** (`key` = the date): the pool is the eligible photos whose `Of` is ≥ the 95th percentile and > 0. Order the pool by `fnv64a("pool|"+ID)`. Take 5 in a row, starting at `(daysSinceEpoch*5) % len(pool)` and wrapping around, while skipping IDs already picked by the other memories of this overview. Detail `Photos` = the whole pool, rarest first.
- `Total` and the detail's `Photos` hold eligible photos only.
- `Build` skips any kind that has nothing to show. The order of `Cards` is trip, person, month, rediscovered.
