# The ⋯ menu

*Last modified: 2026-09-27*

## Summary

The toolbar of a place carried everything at once: layout, sort, the Names and Details switches, Slideshow, Make library…, Clear cache and, in a library, Scan for new photos. Clear cache is not something to look at all the time, and on a phone in landscape the switches took a row the photos needed. A "⋯" button at the end of the path row now holds what need not be on screen.

## Details

- `Menu` (`src/web/js/menu.js`) is one component: a framed button with the accessible name "More", and a floating list (the one place a shadow is allowed) with actions, separators and switches. Items are read each time it opens, so labels such as "Clear cache · 3 files" are those of that moment.
- A switch is drawn by `Toggle`, so it keeps the three visible labels (Names — Shown — Hidden). The row is the control (`role="menuitemcheckbox"`); flipping it leaves the menu open so the change shows behind it. An action closes the menu first, then runs.
- Keyboard: Enter or Space opens it, the first item takes focus, arrows, Home and End move, Escape closes and returns focus to the button, Tab closes. While open it is a `.keyboard-owner`, so the global shortcuts wait — Escape closes the menu and does not clear the selection.
- One menu per pane, moved into each render, so a menu left open by a switch keeps its anchor.
- A pane offers only what its host wired up: Organize's source has the switches only; the slideshow needs `onSlideshowInvoke`, the folder tools `onToolInvoke`.
- Desk: the toolbar keeps the layout and sort order; the menu holds Names, Details, Slideshow, and Make library… (a focused folder, not in a library), Scan for new photos (in a library), Clear cache.
- Phone: the toolbar row is hidden; the menu holds Names, Details, Slideshow and, in a library, Statistics (the head's Statistics button is hidden there). Items are 44px high.
- Along the way: Enter and Space on a focused button or link in a place belonged to the grid (open / select the focused photo), so the Home, Up and ⋯ buttons could not be pressed from the keyboard. `GlobalKeyboard._navigate` now leaves those keys to the control.
- Folder clicks: with a mouse, one click selects a folder so the info panel shows it; a double click or Enter goes in. On a touch screen (`hover: none`) a tap goes straight in.

## Acceptance criteria

- [x] A ⋯ at the end of the path row in Folders, a library and Organize, with an accessible name.
- [x] Names and Details are Toggle switches in the menu, with both state labels, and flip without closing it.
- [x] Slideshow, Make library…, Scan for new photos and Clear cache are in the menu on a desk; none of the folder tools on a phone.
- [x] On a phone the toolbar row is gone and a library's Statistics is in the menu.
- [x] Keyboard: open, move, Escape closes only the menu and refocuses the button.
- [x] A click outside closes the menu.
- [x] With a mouse a click on a folder selects it; a double click goes in; a tap on a touch screen goes in.
- [x] e2e: `menu.spec.js`, plus the updated browse, library, phone, selection bar, overlays, folder info and navigation specs.
